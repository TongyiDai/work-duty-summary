# 记忆写入规范

把确认后的职责画像写进 Agent 记忆，作为后续所有任务的长期锚点。**只有用户明确同意才写。**

## 核心原则

- **存抽象职责锚点，不存原始飞书数据**。记忆里只放浓缩后的职责域 + 关键结果 + 利益相关方 + 时间窗 + 档案文件路径。原始 OKR/任务/消息不进记忆。
- **不直接改记忆主文件**。按本机记忆规范，只在指定的更新笔记目录下新增一个小文件，描述要新增/更新的内容。
- **可刷新**。职责会随时间漂移。笔记里注明时间窗与生成日期，方便未来对比刷新。

## 落点：按宿主 agent 的记忆机制

不同 agent 记忆位置不同。**不要编辑记忆主文件**，新增一个独立小笔记文件描述要沉淀的职责锚点。常见落点：

- **TRAE CLI**：在记忆更新笔记目录新增文件，不改主文件。该目录通常为
  `${TRAE_HOME:-$HOME/.trae}/cli/memories/extensions/ad_hoc/notes/<timestamp>-my-job-responsibilities.md`。
  先确认该目录存在及本机记忆规范，再落地。
- **Claude Code**：写入其 memory 机制，或项目 `CLAUDE.md` 的稳定区块。
- **其他 agent**：写入该 agent 的长期记忆，或项目 `AGENTS.md` 的稳定区块。

文件名示例：`20260817-153000-my-job-responsibilities.md`。宿主无既定机制时，选一个会被后续任务默认读取的稳定位置，并告知用户路径。

## 锚点文件内容格式

```markdown
# 用户工作职责锚点（my-job-responsibilities 生成）

- 时间窗：2026-02-17 ~ 2026-08-17
- 生成日期：2026-08-17
- 档案文件：<职责档案 .md 的绝对路径>
- 用途：后续任务默认对齐本人职责，避免探索/查找偏离本人关注点。

## 职责域（确认版）
1. <职责域>：<关键结果一句话> ｜ 相关方：<角色/团队>
2. ...

## 使用提示
- 探索、查找、判断、排优先级时，以上述职责域为默认关注锚点。
- 本锚点为某时间窗快照，可能过时；用户要求刷新时重新运行 skill 生成新笔记。
```

## 其他 agent

不变的核心：**存抽象锚点、可刷新、不存原始数据、经用户同意**。宿主 agent 的具体记忆 API/约定优先于本文件的示例路径。
